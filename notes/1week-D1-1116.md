# 第一周 D1（11/16）｜用例拆解

> 把大纲的六个场景统一拆成「事件 → 条件 → 动作」三段，全部对应到 starter 模板的三个合约。
> 拆完结论：六个场景是同一套编程模型，只是三段的参数不同。

## 统一拆解框架

```
① 事件（源链 Log）      →  订阅参数：(chainId, contract, topic0)
② 条件（react() 判断）  →  解码 data/topics + 阈值/白名单判断，不满足 return
③ 动作（目标链交易）    →  requestCallbackV_1_0 的 payload + 回调合约函数体
```

## 六个场景逐一拆解

### 场景 1｜链上监控（入门）
| 段 | 拆解 |
|---|---|
| 事件 | ERC-20 `Transfer(address,address,uint256)`，如 USDT 大额转账 |
| 条件 | `amount >= threshold`（模板里的 value 判断就是它的雏形） |
| 动作 | 回调目标链发通知 / 记录，不碰资金 |

### 场景 5｜定时任务（入门）
| 段 | 拆解 |
|---|---|
| 事件 | Cron tick：订阅 `0x…fffFfF` 的 `CRONx_TOPIC_0`（每个 tick 收费） |
| 条件 | 到期检查、巡检逻辑通过 |
| 动作 | 定投买入、自动执行到期操作 |

> 与 1–4 的本质区别：事件不是别人发的 log，而是网络自产的心跳。

### 场景 2｜钱包守护（进阶）
| 段 | 拆解 |
|---|---|
| 事件 | 被守护钱包的 `Transfer` / `approve` |
| 条件 | 收款方不在白名单，或金额异常 → 判定为异常转出 |
| 动作 | 回调目标链：把剩余资产紧急转到安全地址 |

> 难点：③ 是资金操作，需要「同一件事不做两次」+ 金额上限（11/25 加保护的核心）。

### 场景 3｜DeFi 止损/止盈（进阶）
| 段 | 拆解 |
|---|---|
| 事件 | 价格源事件：Uniswap `Sync(uint112,uint112)` / oracle 更新 |
| 条件 | `price <= stopLoss \|\| price >= takeProfit` |
| 动作 | 回调目标链调用 `swap` 卖出 |

> 难点：react() 里拿到的是 reserve，需要换算成价格；滑点保护。

### 场景 4｜跨链价差套利（挑战）
| 段 | 拆解 |
|---|---|
| 事件 | **两条链各一个订阅**（一个 Reactive 合约可多次 subscribe），两个价格源 |
| 条件 | `priceA / priceB >= 1 + fee + profitThreshold`（链间成本：回调 gas + 桥费 + 两链 swap 费） |
| 动作 | 回调便宜那条链买入（卖出端可以再起一个对向合约） |

> 难点：条件里要算清全链路成本；竞争者也在抢，速度即赛道 1 的评审重点。

### 场景 6｜事件驱动的 AI Agent（挑战）
| 段 | 拆解 |
|---|---|
| 事件 | 任意链上事件（资金异动、价格、社媒触发） |
| 条件 | **不在合约里写死**：把事件打包后交给 AI 判断 |
| 动作 | AI 输出决策 → 回调目标链执行 |

> 难点：AI 必须参与运行时决策（评审硬要求），不能只是辅助写代码；AI 在链下、触发与结算在链上。

## 心得

- 六个场景 = 同一个模板换三次参数：换订阅、换 `react()` 里的 if、换回调函数体。模板 README 第 3 节的「改成你自己的项目」表格完全印证。
- 挑选方向时的额外维度：③ 的动作是「通知」还是「动钱」？动钱的场景（2/3/4）必须做防护（重放、上限、暂停），通知类（1/5）门槛低但差异化也低。
- 场景 4 和 6 是组合技：可以「事件 → AI 判断价差是否值得出手 → 套利」，即赛道 1 × 赛道 3 的杂交。
